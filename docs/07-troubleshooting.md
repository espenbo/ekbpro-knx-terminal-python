# Troubleshooting

Start the server with `-v` for a detailed log: `./scada server -v`.
As a service, you find the log with `journalctl -u knxscada -f`.

## KNX

| Problem | Solution |
|---|---|
| **"Could not connect to KNX … Retrying in … s"** | Check `gateway_ip` and that the machine can reach the interface (`ping`). With several network interfaces, set `local_ip`. The firewall must let UDP 3671 through. |
| **Connection is refused, or it keeps connecting and disconnecting** | All tunnels in the IP interface are in use, for example by ETS, another visualisation or Home Assistant. Close other connections, use `routing` with an IP router, or choose another tunnel in the interface. |
| **Values show "–" after start-up** | No telegram for that address has been logged yet. By default the server sends no read requests at start-up (`read_on_start: false`); the value appears with the next telegram. Set `read_on_start: status` to read feedback and sensor addresses at start-up (the status object needs the read flag R in ETS). |
| **A light or actuator switches when the server starts** | Caused by `read_on_start: all` (or older versions): another device answered a read on the control address with an old value. Use `false` or `status`. |
| **Values are shown as raw bytes** | The group address has no DPT in ETS. Set the DPT and export the project again. |
| **A switch does not respond** | Check in the bus monitor (F4) that the telegram goes out (→). If no status comes back, the actuator has no status object, or the status address is not linked. |
| **KNX Secure does not connect** | Check `keyring_file` and `keyring_password`, and that `connection` is `tunneling_secure` or `routing_secure`. The keyring file must be exported from the same project version. |

## The visualisation

| Problem | Solution |
|---|---|
| **"no server" in the top bar** | The server is not running, or you are using a different `config.yaml` than the server. Start it with `./scada server`. |
| **"Permission denied" on the socket** | Your user is not in the group of the socket owner. See [Operation and SSH](05-operation-and-ssh.md#access-and-security). |
| **Strange characters or boxes instead of lines** | The terminal font lacks box-drawing or braille characters, or the terminal is not set to UTF-8. Change the font, or set `ui.ascii: true` for the charts. |
| **Large digits are unreadable** | Set `ui.big_digits: false` (default). |
| **The F-keys do not work over SSH** | Some clients, PuTTY among them, send different codes. In PuTTY, set *Keyboard → Function keys* to "Xterm R6". The menu can always be used with the arrow keys and Enter, or with the mouse. |
| **`Ctrl+Q` does not work** | The terminal uses `Ctrl+Q` for flow control (XON). Use `F10`, `Ctrl+C` or the menu entry "Quit". |
| **Arrow keys do not work in the floor plan** | Use `PgUp` / `PgDn`, `1`–`9` or `n` / `p`, or click the floor tabs. |
| **Slow over SSH** | Use a smaller terminal window or a faster connection. The screensaver reduces the traffic when nobody is using the screen. |
| **The rooms are empty in F2** | The project has neither ETS functions nor a usable group address structure. See [Using your own KNX project](02-own-project.md#3-how-the-visualisation-is-built). |
| **Changes in ETS are not shown** | Export the `.knxproj` again, run `./scada import`, and restart the server and the visualisation. |
| **Wrong language** | The order is `./scada tui --language` → the user's own choice (`Ctrl+L`, stored in `~/.config/knxscada/ui.json`) → `ui.language` → English. Pick the language again with `Ctrl+L`, or delete `ui.json`. |
| **Event log or alarms in another language than the menus** | These texts are generated by the server in its language (`ui.language` when the server started) and stored in the database. Older entries keep the language they were written in. Restart the server after changing `ui.language`. |
| **The terminal is messed up after a crash** | Run `reset`. On a normal exit the screen is cleared automatically. |

## The project

| Problem | Solution |
|---|---|
| **"Cannot find the project file …"** | Check `project.file`. Relative paths are resolved from the directory `config.yaml` is in. |
| **Wrong password, or the project cannot be read** | Set `project.password`. ETS 4–6 are supported, but projects from very old ETS versions must be opened and exported again in a newer ETS. |
| **"Could not find application_program_ref …"** | A warning from xknxproject about a device without an application program, for example a USB interface. It is harmless. |

## Information for a bug report

Include:

- the output of `./scada info`
- the last lines from `./scada server -v`
- the terminal and SSH client you use
- a screenshot
